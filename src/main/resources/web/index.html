PERFORMANCE ENGINEERING · JAVA 8+

Low-latency lab.

Work through allocation profiles, JMH benchmarking, GC pauses and trading-system tail latency. Learn the methodology before tuning.

Measure first. Optimise second.

Zero-GC is a measured steady-state objective, not a JVM guarantee. Compare throughput, p99/p99.9 latency, allocations per operation and GC pauses under repeatable workloads.

Benchmark workflow

1. Establish a baseline using JMH with warm-up, forks and realistic inputs. 2. Capture allocation hotspots with Java Flight Recorder. 3. Remove avoidable boxing and hot-path allocation. 4. Repeat under load and compare tail latency. 5. Inspect GC logs before changing collector flags.

JMH and JFR require a compatible local JDK and tooling; this module teaches the workflow without claiming to execute a profiler inside the browser.

SET UP ONCE

Install in three steps

  1. Download the devflow-intellij artifact from a successful GitHub Actions build. Unzip the artifact once to find the plugin ZIP.
  2. In IntelliJ IDEA, open Settings → Plugins → ⚙ → Install Plugin from Disk and select that plugin ZIP.
  3. Open View → Tool Windows → DevFlow. The bundled local app starts automatically.

Targets IntelliJ IDEA 2025.3.1 and later. Uses the IDE's bundled Java runtime and embedded browser. See the repository for build and compatibility checks.

Official rounds

0 ROUNDS

Handicap methodology: each segment is rated 0–54, combining speed (50%), typing accuracy (40%) and rhythm consistency (10%). A round is the mean of its three segments; your index averages the best three of your eight latest rounds. Fewer than three rounds produce a provisional index. This is a custom training metric, not an industry-standard handicap.
